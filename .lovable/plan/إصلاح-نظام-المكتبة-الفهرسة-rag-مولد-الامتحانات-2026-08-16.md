# إصلاح نظام المكتبة + الفهرسة + RAG + مولد الامتحانات

## أولاً: نتيجة التحليل (السبب الحقيقي)

فحصت `modrek-worker`, `modrek-retrieve`, `modrek-ai-study`, `modrek-ai-exams`, `library-*`, وجداول `knowledge_sources / knowledge_source_versions / knowledge_units / content_chunks / processing_jobs`.

**1) سبب توقف الكتب الكبيرة وأخطاء 402**
- الكتب أكبر من 80MB فقط هي التي تمرّ على مسار Gemini File API (`PDF_LOCAL_FALLBACK_LIMIT_BYTES = 80MB`). كتاب 30MB يمرّ على المسار المحلي.
- في المسار المحلي، إذا كانت طبقة النص ضعيفة (كتاب مصور/مسحوب سكانر) يُقطع مجموعة صفحات من PDF ثم تُرسل **كاملة داخل الطلب كـ base64** إلى `chat/completions` (`geminiExtractFromBytes`) — أي بروميت ضخم جدًا.
- OpenRouter يحسب الرصيد المطلوب = (توكنز الإدخال الضخمة + الحد الأقصى للإخراج). لذلك تظهر: `402 requires more credits… requested up to 65536 tokens`. المشكلة ليست `max_tokens` وحدها بل **حجم الإدخال** + عدم وجود ميزانية توكنز حقيقية.
- `EXTRACT_PAGE_MAX_ATTEMPTS = 30` و402 غير مُصنّف كخطأ نهائي → كل دفعة صفحات تُعيد المحاولة 30 مرة (وهو ما تظهره الصور: `30/30 محاولة` لعشرات الدفعات) = آلاف طلبات فاشلة واستهلاك رصيد بلا فائدة.
- `merge_text` يفشل عندما تبقى دفعة صفحات فاشلة → الكتاب كله `failed` مع 0 أحرف مستخرجة رغم وجود 190 وحدة (نفس الصورة الأولى).

**2) سبب عدم وصول المساعد للمحتوى الصحيح**
- `modrek-ai-study` ينادي `modrek-retrieve` **بدون أي filters** ويترك الفلترة للسياق العام فقط، ثم يضيف بحثًا في `library_books` بـ `ilike` على كل المكتبة (`access_tier=free`) بدون صف/شعبة.
- `modrek-ai-exams` (`retrieveStudyContext`) يبحث بـ `ilike` على `knowledge_units` ويفلتر بالمادة فقط، و`content_chunks` بـ `textSearch` **بدون أي فلترة صف/شعبة/نوع تعليم** → احتمال خلط رياضيات أولى/ثانية/ثالثة ثانوي.
- لا توجد طبقة فهم للسؤال: «الدرس الخامس» لا يُترجم إلى درس حقيقي؛ لا يوجد فهرس دروس مرقّم مرتبط بالكتاب.
- لا توجد حالة صفحة/درس مستقلة تسمح بترتيب المحتوى أو الاستشهاد بالصفحات بدقة.

**3) ما هو سليم ويُعاد استخدامه**
- بنية الجداول (`knowledge_sources → versions → units → content_chunks`) + `pgvector` + `search_tsv` + دالة `modrek_hybrid_search` (بها فلاتر stage/grade/section/track/subject جاهزة وغير مستخدمة بالكامل).
- نظام الوظائف (`processing_jobs`, `processing_events`) وطبقة مزوّد الذكاء الموحّدة.
- لن يُحذف أي كتاب أو chunk أو embedding.

## ثانياً: خطة التنفيذ

### المرحلة 1 — إيقاف نزيف 402 وميزانية التوكنز (أولوية قصوى)
- تصنيف `402 / insufficient credits` كخطأ **نهائي غير قابل للإعادة**: إيقاف مرحلة LLM للنسخة بحالة `paused_no_credits` مع رسالة واضحة للمطور، وحفظ كل ما تم إنجازه.
- إضافة قاطع دائرة (circuit breaker) على مستوى النسخة: بعد أول 402 لا تُرسل أي طلبات أخرى للمزوّد لنفس الكتاب.
- خفض `EXTRACT_PAGE_MAX_ATTEMPTS` إلى 5 مع backoff تصاعدي، وتصنيف الأخطاء (رصيد/حد معدل/مهلة/بيانات).
- ميزانية توكنز محسوبة لكل طلب: `max_tokens` مشتق من عدد الصفحات وحجم النص الفعلي (لا قيمة ثابتة كبيرة)، وحدّ أقصى صارم لحجم الإدخال قبل الإرسال.

### المرحلة 2 — Pipeline استخراج بدون LLM افتراضيًا
- الترتيب الجديد لكل دفعة صفحات (1–4 صفحات):
  1. استخراج طبقة نص PDF محليًا (pdf.js) — بدون أي LLM.
  2. إذا كانت الصفحة فقيرة نصًا فقط: تحويلها إلى **صورة صفحة واحدة مضغوطة** وإرسالها لـ OCR (بدل إرسال PDF كامل base64) → تقليل الإدخال بأكثر من 90%.
  3. LLM للبنية/العناوين فقط عند الحاجة، وبعد محاولة كشف العناوين خوارزميًا (regex عربي: وحدة/باب/فصل/درس/تدريبات/تعريف/قانون).
- خفض حد استخدام Gemini File API من 80MB إلى ~15MB بحيث تستفيد الكتب الكبيرة من مسار الملف بدل base64.

### المرحلة 3 — حالة الصفحة + Resume + منع التكرار (Migration آمنة)
- جدول جديد `knowledge_page_state`: `version_id, page_number, extraction_status, ocr_status, chunk_status, embedding_status, retry_count, error_message, content_hash, timestamps` + فريد `(version_id, page_number)`.
- `merge_text` لا يفشل الكتاب: يكمل بالصفحات المكتملة ويسجّل الفاشلة في قائمة `failed_pages`.
- Idempotency: مفتاح فريد `(version_id, page_number, chunk_index)` + `content_hash` للـ chunks، وتخطي أي chunk/embedding موجود مسبقًا.
- إعادة التشغيل تبدأ من الصفحات `pending/failed` فقط.

### المرحلة 4 — فهرس الدروس وبنية الكتاب
- جدول `knowledge_lesson_index`: `source_id, unit_id, lesson_number, unit_number, kind, title, page_start, page_end` مبني خوارزميًا من العناوين المكتشفة + ترتيبها.
- كل chunk يحمل metadata: `book_id, subject_id, grade_id, track_id, section_id, term, academic_year, unit_number, lesson_number, page_from/page_to`.

### المرحلة 5 — Query Understanding + RAG محصّن
- طبقة فهم سؤال (خفيفة، خوارزمية أولًا + LLM عند الغموض) تُخرِج: `intent` (explain / exam_lesson / exam_unit / exam_full)، `subject`، `lesson_number`، `unit_number`.
- تحويل الأرقام العربية الكتابية («الخامس» → 5).
- **فلترة إلزامية** قبل أي بحث: `grade_id + track_id + section_id + education_type + subject_id + academic_year` من ملف الطالب — تمرير هذه الفلاتر فعليًا إلى `modrek_hybrid_search` من `modrek-ai-study` و`modrek-ai-exams` وإزالة أي بحث `ilike` عام على كل المكتبة.
- إذا لم يوجد درس مطابق: رسالة صريحة «لم أجد هذا الدرس في كتابك» بدون تأليف.
- كل إجابة منهجية تُعرض مع مصدرها: اسم الكتاب + الدرس + الصفحات.

### المرحلة 6 — مولد الامتحانات من المحتوى الحقيقي
- بناء Context من chunks الدرس/الوحدة/الكتاب بالترتيب، بحد أقصى منظّم للتوكنز (تلخيص هرمي للمنهج الكامل بدل إرسال كل شيء).
- دعم: MCQ / صح وخطأ / قصير / مسائل، مع عدد أسئلة ومستوى صعوبة، ومنع أي سؤال خارج المحتوى المسترجع.

### المرحلة 7 — لوحة المطور
- في صفحة تفاصيل المصدر: إجمالي الصفحات، المكتملة، الجارية، الفاشلة، عدد الـchunks/embeddings، نسبة الإنجاز، وقت البدء/آخر تحديث، وسبب الخطأ المصنّف.
- زر **«إعادة معالجة الصفحات الفاشلة فقط»** + بانر واضح عند `paused_no_credits`.

### المرحلة 8 — اختبارات
- اختبارات فعلية على: PDF نصي صغير، ~100 صفحة، ~300 صفحة، كتاب ≥30MB مصور، وقطع الاتصال في المنتصف (Resume)، وإعادة صفحة فاشلة، وعدم تكرار chunks.
- اختبارات عزل: أولى/ثانية/ثالثة ثانوي + رياضيات، عام مقابل أزهري، علمي مقابل أدبي — نفس السؤال «اشرح الدرس الخامس» يجب أن يعطي كتاب الطالب فقط.

## ملاحظات تقنية
- كل تغييرات القاعدة عبر migrations إضافية فقط (جداول/أعمدة/فهارس جديدة) — **بدون حذف أو تعديل بيانات قائمة**.
- الكتب المفهرسة حاليًا تبقى تعمل؛ فهرس الدروس وحالة الصفحات يمكن بناؤها لاحقًا لكل كتاب على حدة عبر عملية «إعادة فهرسة قابلة للمتابعة» اختيارية.
- ملاحظة مهمة: خطأ 402 هو **نقص رصيد فعلي في حساب مزوّد الذكاء**. الخطة توقف الهدر وتحفظ التقدم وتخبرك بوضوح، لكن إتمام OCR للكتب المصورة سيحتاج رصيدًا متاحًا.
