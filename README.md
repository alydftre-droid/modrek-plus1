# modrekplus 

اسم المشروع: أزهاريون

الهدف: منصة تعلّيمية متكاملة موجهة لطلبة الأزهر (مراحل: ابتدائي/إعدادي/ثانوي — تخصص: علمي/أدبي/شرعي) تجمع المناهج، الكتب (PDF)، فيديوهات شرح، وتمكّن المعلمين والمطور من إدارة المحتوى والتحكم الكامل، بالإضافة لمساعد ذكي يستطيع الإجابة من الكتب المرفوعة.

الميزة التنافسية: تقسيم دقيق لكل مادة → أقسام داخلية (نحو، صرف، بلاغة.. إلخ)، تجربة دخول متطورة/آمنة، مساعد ذكي يجيب من كتب المعلّم/المطوّر، لوحة تحكّم قوية للمطوّر/المعلّم مع سلوك موافقة للمعلمين الجدد.


2 — المستخدمون (Roles) وصلاحياتهم

1. طالب (Student)

إمكانية التسجيل السريع: Google OAuth أو البريد الإلكتروني + اسم مستخدم.

واجهة شخصية (Student Dashboard): يظهر له المراحل → الصفوف → المواد → أقسام المادة (شرح فيديو، كتب PDF، اختبارات، المساعد الذكي، شات دعم).

إعدادات: تغيير كلمة المرور، رؤية كود الطالب الفريد، إحصائيات الاستخدام (يومي/شهري — ساعات ودقائق)، تحميل الكتب، مشاهدة الفيديوهات، التواصل مع الدعم/المعلم.



2. معلم (Teacher) — بعد التسجيل يطلب موافقة المطوّر (approval workflow).

عند الموافقة: صلاحيات رفع/تعديل/حذف فيديوهات، رفع كتب PDF وربطها بالمادة/الصف، إنشاء اختبارات، مشاهدة تقارير طلابية (الوقت المستغرق، عدد المشاهدات).

لا يمكنه إنشاء حساب معلم يدخل مباشرة بدون موافقة المطوّر — يظهر له حالة الطلب حتى الموافقة.



3. مطوّر/مدير المنصة (Developer / Admin) — صلاحيات كاملة.

يوافق أو يرفض طلبات المعلمين.

يضيف/يحذف مواد/أقسام، يرفع فيديو/كتب، يرسل إشعارات لمستخدمين محددين أو لجميع الطلاب، يحظر حسابات، يعدل أي عنصر في الواجهة، يرى إحصاءات كاملة للمنصة.



4. دعم (Support) — حسابات تعليمية/فنية تردّ على شات الدعم (ممكن يكونوا من المعلّمين أو فريق المطوّرين).



3 — سيناريو تسجيل الدخول / إنشاء الحساب — UX مفصل (تركيز كبير هنا كما طلبت)

3.1 شاشة البداية (Landing)

زر تسجيل / تسجيل دخول واضح في الركن فوق اليمين.

للطلاب: “سجّل بـ Google” و “سجّل بالبريد الإلكتروني” + خانة اسم مستخدم اختياري.

للمعلّم: زر “تسجيل معلّم” يظهر فورًا نافذة تطلب بيانات إثبات (اسم، جهة عمل، بطاقة مدرسية/رقم وظيفي، البريد، رقم تليفون) + زر رفع ملف إثبات (صورة). بعد الإرسال يظهر له: "تم إرسال طلبك للمطوّر — قيد المراجعة" مع أيقونة ساعة كبيرة/حالة الطلب. فقط بعد موافقة المطوّر يتم تفعيل الحساب. (سلوك معتمد لدى أنظمة edu سليمة).


3.2 عملية التسجيل (واجبات الأمان)

التحقّق بالبريد الإلكتروني (email verification link).

كلمات مرور لازم تتبع قواعد: min 8 حروف، حرف كبير واحد على الأقل، رقم، رمز خاص — عرض مؤشر قوة كلمة المرور.

خيار استعادة كلمة المرور عبر البريد.

(اختياري لاحقًا) 2FA SMS/Google Authenticator لمطوّر/حسابات عالية الصلاحية.


3.3 شاشة الدخول (Login) — UX/UI مفصّل ومركز على تجنّب الأخطاء:

تصميم بسيط، حقول واضحة، توضيحات خطأ ذكية:

الحقول: البريد/المستخدم + كلمة المرور + زر "الدخول" + روابط: "نسيت كلمة السر" و"تسجيل جديد".

زر تسجيل الدخول بـ Google ظاهر.

رسائل الأخطاء الشائعة وكيف تظهر للمستخدم:

1. هل نسيت كلمة السر؟ — "البريد أو كلمة المرور غير صحيحة" — اقترح: "جرب استعادة كلمة السر" + رابط استعادة.


2. حساب معلّم لم يُفعّل بعد — رسالة خاصة: "حسابك كمعلم قيد المراجعة — تم إرسال إشعار للمطوّر. حال قبول الطلب سيصل لك إشعار." (يمنع الدخول)


3. حظر/تعليق — "حسابك موقوف — تواصل مع الدعم" + زر تواصل فوري.


4. مشاكل OAuth (Google) — "فشل تسجيل الدخول عبر Google. جرّب تسجيل الدخول بالبريد أو اتأكد من صلاحيات Google Account." — (رابط لإصلاح المشكلة: تحقق من السماح بالوصول).


5. انتهاء صلاحية الجلسة / مشاكل الكوكيز — "يبدو أن ملف تعريف الارتباط مغلق؛ فعل الكوكيز أو استخدم نافذة خاصة."



لكل رسالة خطأ، عرض زر "تواصل مع الدعم" يفتح شات مباشر أو يرسل إشعارًا للمطوّر/فريق الدعم مع لوج للخطأ (timestamp، device info).


3.4 تجربة الـ Onboarding بعد أول تسجيل دخول (Student)

يُعرض للطالب شريط خطوات صغير (progress bar): اختيار المرحلة → اختر الصف → عرض المواد المقترحة → دعوة لتفعيل الإشعارات.

عند اختيار الصف (مثلاً: ثالث ثانوي) يظهر فوق شريط يطلب تحديد "علمي / أدبي / شرعي" ثم تظهر المواد المرتبة كبطاقات أو أزرار. عند الضغط على أي مادة (مثلاً: العربية → النحو) يفتح له صفحة المادة.


4 — تنظيم المحتوى داخل المادة

كل مادة صفحة منفصلة تحتوي على:

تبويبات (Tabs): كتب المقرّر (PDFs)، شرح الفيديوهات (lessons)، المساعد الذكي (chat with PDF/notes)، اختبارات وملفات (quizzes & resources)، منتدى/شات الأسئلة.

من داخل الشرح: كل درس يظهر كـ card: عنوان، وصف قصير، مدة الفيديو، زر تشغيل، زر تنزيل المرفقات.

نظام صلاحيات: فقط المعلم/المطوّر يمكنهم رفع/تعديل/حذف محتوى داخل المادة.


5 — المساعد الذكي (AI Assistant) — المواصفات

الهدف: بوت ذكي يستطيع الإجابة على أسئلة الطلبة بناءً على الكتب/الملفات المرفوعة من قبل المعلم/المطوّر، ومصادر موثوقة داخل المنصة (لا يجيب من الإنترنت إلا إذا فعلنا دمج خارجي لاحقًا).

متطلبات وظيفية:

رفع ملف PDF من قبل المعلم/المطوّر مرتبط بالمادة (مثلاً: كتاب عربي ثالث ثانوي).

خطوات المعالجة: تحويل PDF → استخراج نص → تقسيم إلى فقرات/قطع (chunking) → حساب embeddings (vectorization) → تخزين في قاعدة نُدُلات (Vector DB مثل Pinecone/Weaviate/FAISS).

بوت الأسئلة يستخدم الـvector search لاستدعاء مقاطع مرجعية ومن ثم نموذج LLM لصياغة الإجابة مع إظهار مصدر (مرجع الصفحة/المقطع). أدوات أمثلة موجودة (ChatPDF/pdf.ai/ChatPDF-like). 

واجهة المستخدم للمساعد: صندوق دردشة داخل كل مادة، زر "ارفع كتاب للبحث" للمعلّم، زر "اطلب شرح" للطالب، وعرض الاقتباس/صفحة المصدر عند الإجابة.

قيود أمان: لا تسمح للطالب برفع ملفات عامة إلى قاعدة المعرفة المشتركة إلا بعد موافقة المطوّر/المعلّم.


أمور تقنية مُقترحة:

استخدام service لبناء pipeline PDF→embedding (مثال: use open-source tools أو خدمات جاهزة مثل pdf.ai أو Denser.ai كمراجع للتصميم). 

سجل استعلامات للـAI (logging) وفلترة مخرجات لإزالة أي محتوى غير لائق أو خطأ معلوماتي — مراجعة بشرية ممكنة للمواد الحساسة.


6 — لوحة المطوّر / لوحة المعلّم (Admin / Teacher dashboards)

لوحة المطوّر (Admin):

إحصاءات شاملة: عدد الطلاب المسجلين، عدد المعلمين، استخدام يومي/شهري، متوسط وقت الاستماع لكل مادة، وتحليل نشاط المنصة.

إدارة المستخدمين: عرض كل الطلاب/المعلمين مع كود الطالب، تاريخ التسجيل، حالة الحساب (مفعل/معلق)، إمكانية حظر/إلغاء تفعيل.

إدارة المحتوى: إضافة/تعديل/حذف مواد، أقسام، دروس، كتب، رفع فيديوهات.

إدارة طلبات المعلمين: قائمة طلبات التفعيل (approve/reject) مع سبب الرفض وإشعار تلقائي للمستخدم.

إرسال إشعارات: إرسال إشعارات Push/Email لمستخدم معين (باستخدام الكود) أو لجميع الطلاب.

سجلّ نشاط تفصيلي (audit logs) لكل التعديلات.
لوحة المعلّم (بعد الموافقة):

إمكانية رفع كتب PDF، رفع فيديوهات (مع وصف ومدة)، تمييز دروس كمحتوى رسمي، مشاهدة إحصاءات لطلاب المادة، إرسال رسالة/اعلان لطلاب المادة.


7 — الأخطاء الشائعة وخطوات التعامل (ركزت عليها كما طلبت)

1. مشكلة: "كلمة السر/البريد غير صحيحة"

واجهة تعرض: نص توضيحي + رابط نسيت كلمة السر + محاولة إعادة تفعيل الحساب إن لم يؤكد البريد.

نظام تحذير بعد 5 محاولات فاشلة: قفل مؤقّت 15 دقيقة + رسالة “تم قفل الحساب مؤقتًا لحمايتك”.



2. OAuth Google يفشل (Permission/consent issue)

توجيه المستخدم ليتأكد من إعطاء صلاحيات الحساب أو تجربة متصفح آخر/وضع خاص. سجل الخطأ مع تفاصيل OAuth (error code) لمطوّر النظام.



3. حساب معلم غير مفعل

رسالة شرح واضحة: "تم إرسال طلب التفعيل للمطوّر — سيصلك إشعار عند الموافقة. لو العجلة تواصل مع الدعم." (لا يسمح بالدخول).



4. ملفات PDF لا تُحمّل أو فيديوهات لا تُعرض

حالتين: حجم ملف كبير/تنسيق غير مدعوم → إظهار الحد الأقصى للحجم وشوية نصائح (ضغط PDF، mp4 H264).

مشكلة التخزين أو CDN → fallbacks: رسالة للمستخدم وإرسال لوج للمطوّر.



5. المستخدم لا يستقبل إشعارات

تحقق من تفعيل الإشعارات، إعطاء أذونات المتصفح/الجهاز، وإمكانية إرسال اختبار من لوحة المطوّر.



6. المساعد الذكي يجيب إجابة خاطئة

زر “ابلاغ عن إجابة خاطئة” يظهر للطالب، ويرتبط بفلتر مراجعة للمطوّر/معلم. سجل مصدر الإجابة (الصفحة/المقطع) لسهولة التصحيح.



7. جلسة تنتهي فجأة

تحقق من سياسة الجلسة (session timeout)، كوكيز، واخطَر المستخدم بطريقة واضحة وامكانية إعادة الدخول/استعادة الجلسة.




8 — المتطلّبات التقنية المقترحة (Tech Stack & Infra)

Frontend: React + Tailwind CSS (واجهة حديثة وسريعة)، أو Next.js لSSR إذا مطلوب SEO لصفحة الهبوط.

Mobile: React Native أو Flutter (لنسخة موبايل لاحقًا).

Backend: Node.js (Express/NestJS) أو Python (Django/DRF) — أيّ منهما مناسب.

DB: PostgreSQL للعلاقات + Redis للكاش و-session.

Storage: S3 (AWS) أو MinIO، + CDN (CloudFront أو Cloudflare) للفيديوهات.

Media processing: تحويل الفيديو (FFmpeg) وthumbnail generation.

AI Pipeline: خدمة embeddings + Vector DB (Pinecone / Weaviate / FAISS self-hosted) + LLM API (يمكن استخدام نموذج تجاري أو self-hosted لاحقًا). (مراجع لأدوات chat-with-pdf). 

Authentication: OAuth2 (Google) + JWT sessions + email verification + password rules.

Logging & Monitoring: ELK / Grafana / Sentry للـerrors.

Deployment: Docker + Kubernetes أو managed services (ECS/EKS).

2) المساعد الذكي — استخدام Gemini 2.5

موديل محدد: المساعد الذكي هيتصل بـ Gemini 2.5 كمحرك LLM الأساسي للردود ولبناء وظيفة RAG (Retrieval-Augmented Generation) على الكتب/الـPDFs المرفوعة.

تدفق التنفيذ المقترح:

1. المعلم/المطوّر يرفع PDF ويربطه بالمادة → النظام يستخرج النص ويجزّئه إلى chunks.


2. نحسب embeddings لكل chunk ونخزنها في Vector DB (مثل Pinecone/Weaviate/FAISS).


3. عند سؤال الطالب، نبحث عن أقرب chunks (vector search) ونبعت المحتوى المرجعي ده مع الـprompt إلى Gemini 2.5 لتوليد إجابة موثقة (مع ذكر المراجع: اسم الملف + رقم الصفحة/المقطع).

تدفق التنفيذ المقترح:

const axios = require('axios');

async function askGemini(prompt, contextChunks) {
  const GEMINI_API_KEY = process.env.GEMINI_API_KEY; // لا تضع المفتاح هنا في الكود
  const endpoint = 'https://api.gemini.example/v1/generate'; // ضع الـendpoint الصحيح تبع مزود الخدمة

  const input = {
    model: 'gemini-2.5',
    prompt: `Use the following context to answer in Arabic. Context:\n${contextChunks.join('\n---\n')}\n\nQuestion: ${prompt}`,
    max_tokens: 800,
    temperature: 0.1,
    // other params...
  };

  const res = await axios.post(endpoint, input, {
    headers: {
      'Authorization': `Bearer ${GEMINI_API_KEY}`,
      'Content-Type': 'application/json'
    },
    timeout: 20000
  });

  return res.data;
}
