---
name: Demo Accounts Read-Only Security Boundary
description: Demo accounts see everything but every write is blocked by DB triggers + edge guards; identity from is_demo/demo_accounts/@modrekplus.demo email only
type: constraint
---
- Demo accounts = full read visibility of the real platform (no page, button or data hidden) + ABSOLUTE read-only. Never implement demo restrictions by hiding UI. ONE exception: «معلومات المنصة» (PlatformInfoSettings) is hidden AND route-blocked for demo (admin email/password, service keys).
- Demo identity is resolved server-side only via `public.current_user_is_demo()`, which checks `profiles.is_demo`, `demo_accounts.user_id`, AND `auth.users.email LIKE '%@modrekplus.demo'` (`public.is_demo_email`). Never email from the client, JWT metadata, headers or localStorage.
- ROOT CAUSE of the 2026-09 breach: demo accounts existed in `auth.users` with `is_demo = false` and no `demo_accounts` row (non-atomic creation), so `current_user_is_demo()` returned false and all 290 triggers allowed writes. Fixed by: the email fallback above, row trigger `zzy_force_demo_flag` on `public.profiles` (forces `is_demo`/`is_test_account` for demo-domain accounts), a backfill, and an atomic `createDemoAccount` in `admin-demo-accounts` that deletes the auth user when any later step fails and verifies `is_demo = true` before returning.
- DB boundary: `assert_not_demo()` (raises `DEMO_READ_ONLY`, SQLSTATE 42501), `block_demo_write()`, triggers `zzz_demo_read_only` + `zzz_demo_read_only_truncate` on every public table, event trigger `zzz_demo_read_only_autoattach` for new tables. Migrations: `drizzle/migrations/0032`, `0033`, `0036_demo_identity_hardening.sql`. Applied on preview AND production (`qteuqfntsocsdbjmdvmr`).
- `platform_settings` "Admins can manage settings" policy requires `NOT current_user_is_demo()`; sensitive keys (supabase_url/anon key, worker shared keys, developer contact) are readable by admins only, so demo sees only the 31 public keys.
- Edge boundary: `supabase/functions/_shared/demoGuard.ts` (`blockDemoWrites`, `isDemoUserId`) returns 403 `DEMO_READ_ONLY`. Guard on 42 functions; action-selective in `bunny-storage`, `bunny-stream`, `zoom-live`, `library-admin`, `admin-teacher-scope`. Read-only search paths (`library-search`, `modrek-retrieve`) stay unguarded on purpose (cache/log writes only). Any NEW mutating edge function must call the guard.
- Frontend `src/lib/demoReadOnly.ts` only shows the Arabic toast; `src/hooks/useIsDemoAccount.ts` only hides the platform-info screen. Neither is the protection.
- Verify with `DEMO_TEST_DB_URL=$EXTERNAL_SUPABASE_DB_URL node scripts/test-demo-read-only.mjs` (rolled-back transactions, 71 checks, prefers a demo account holding the admin role). Full report: `docs/DEMO_READ_ONLY_SECURITY.md`.
